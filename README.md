## 功能一览

| 模块 | 说明 |
|------|------|
| **数据分析** | 录入面板可读数据与五维能力，输出两轴（高压 / 低爆）评分、判定档位、硬触发项与定向归因 |
| **历史记录** | 本机留存历次结果，支持筛选、排序、备注、批量管理与两条记录对比；可导出 / 导入 JSON |
| **历史分析** | 对多次记录做聚合归因：判定分布、风险趋势、模式差异、高频驱动项与输入相关性 |
| **爆率模拟** | 只读快照的单变量试算，观察改动某一项会怎样；不回写录入、不写入历史、不参与统计 |

## 推测模型要点

- **两轴分离**：高压轴（对手与人机强度）与低爆轴（爆率与收益压制）独立计分，同时越线才判双重黑屋。来源明示「低爆率与高对局强度并非必然同时出现」。
- **五系数合成**：账号基础 40% / 当局表现 35% / 战损补偿 15% / 收益额度 7% / 特殊事件 3%。其中收益额度、行为画像与组队方式以乘法闸门形式参与，而非简单加权，以复现「越强越难出货」的实测形态。
- **阈值动态上浮**：判定阈值不是固定值，按加权覆盖率与样本量在 58 至 72 区间上浮，样本越少越保守；结论翻转还会经扰动重算验证。
- **冲突取保守**：同一指标存在来源分歧时（如撤离率安全上限 35% 与 45% 两说），取更窄区间，判定可能偏严，冲突项在报告中逐条登记。
- **时长只有小时一个单位**：录入、计算、报告、模拟、历史记录显示全部以小时为准，不存在分钟与小时的混算路径；阈值在小尺度上以三位小数保留精度（如 0.167 小时），换算关系仅作为注释存在。
- **官方未公示项一律不建模**：隐藏分公式、匹配权重、局内爆率、炫彩掉率均无官方出处。社区流传的两组「精确」爆率互相冲突，按冲突取保守原则不予替换。

## 部署到 GitHub Pages

1. 将 `index.html` 与 `README.md` 推送到仓库根目录。
2. 进入仓库 `Settings → Pages`，`Source` 选择 **Deploy from a branch**，分支选 `main`，目录选 `/ (root)`。
3. 等待约一分钟，访问 `https://<用户名>.github.io/<仓库名>/`。

若仓库不是 `<用户名>.github.io` 形式的用户页，站点会挂在子路径下，本应用已做相对路径兼容，无需额外配置。

## 本地使用

- **直接打开**：双击 `index.html` 即可离线使用。
- **数据持久化**：历史记录、草稿与迁移标记保存在当前浏览器的 `localStorage`，与浏览器或设备绑定；清除站点数据或无痕模式会导致记录丢失。
- **跨设备迁移**：在旧设备「历史记录 → 导出」得到 JSON，在新设备「导入」即可；旧版本导出的 JSON 同样兼容，缺失字段会按当前算法补算。
