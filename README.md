## 🛠 实现方式

系统之所以能做到「零抓取却像原生一样好用」，关键在于以下实现思路：

- **纯窗口挂载（零爬虫）**
  通过浏览器原生 `<iframe>` 直接嵌入 moligod 对应页面，本工具**不请求任何接口、不解析页面源码、不缓存任何数据文件**，所有可见内容均由源站实时渲染。

- **CSS 视口裁剪**
  利用 `transform: scale` 配合 `position: absolute` 偏移 iframe，只展示目标内容区（排除左侧固定导航与顶部广告栏），实现「聚焦内容、隐藏冗余」。

- **可缩放 / 可滚动挂载组件**
  挂载容器支持 `overflow: auto` 自由滚动，缩放比以变量驱动（20%–300%，支持输入框自定义百分比与 +/- 步进），并对齐源站坐标，避免二级详情浮窗被边框裁切。

- **单文件架构**
  全部 HTML / CSS / JS 内联于一个 `.html` 文件，引用计数 `0` 个 `<script src="http…">`，离线可用、跨平台、即拷即跑。

- **本地持久化**
  用户数据通过浏览器 `localStorage` 键值存储落地（改枪码库、文件夹、分类、历史记录、草稿等），纯本地读写，关闭或刷新后再次进入直接读取。

- **社区因子模型**
  黑屋匹配推测由「触发面因子 + 阈值规格表」驱动：模型内所有阈值只在规格表中定义，每个结论都能回溯到对应来源；对同一指标存在来源分歧时，取更保守的窄区间作为「最优」判定。

- **跨版本数据迁移**
  历史记录采用「新键写入 + 旧键一次性归集 + 旧键保留备份」策略：首次加载 v8.5 时自动把 `delta_blackroom_history_v6` / `v3` 等旧键记录迁入新键 `delta_blackroom_history_v85`，并写入迁移标记防止误删复活；导入接口对旧版导出 JSON 做字段归一化与按当前算法补算，保证跨设备、跨版本不丢历史。

## 部署到 GitHub Pages

本仓库根目录的 `index.html` 即为站点入口，按以下步骤即可上线：

1. **推送代码**：将本仓库（含 `index.html` 与 `README.md`）推送到你的 GitHub 仓库。
2. **开启 Pages**：进入仓库 `Settings → Pages`，在 `Build and deployment` 下将 `Source` 设为 **Deploy from a branch**，分支选择 **main**（或 master），目录选择 **/ (root)**。
3. **访问站点**：保存后等待约 1 分钟，访问 `https://<你的用户名>.github.io/<仓库名>/` 即可。

> 提示：若仓库名不是 `<用户名>.github.io` 形式的用户/组织页，站点会挂在 `/<仓库名>/` 子路径下，本应用已做相对路径兼容，无需额外配置。

## 本地使用

- **直接打开**：双击 `index.html` 即可在浏览器中离线使用（挂载区需联网访问源站）。
- **数据持久化**：改枪码、文件夹、分类、历史与草稿均保存在当前浏览器的 `localStorage`，与打开该文件的浏览器 / 设备绑定；更换浏览器、清除站点数据或使用无痕模式会导致记录丢失。
- **跨设备迁移历史**：在旧设备「历史记录 → 导出 JSON」，在新设备「导入文件 / 粘贴导入」即可；v8.4 及更早版本的导出格式完全兼容（缺结论字段的旧记录会按当前算法补算）。
